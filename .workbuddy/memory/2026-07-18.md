## 相机页三项优化

### 1. 默认进入相机为取景框折叠态
- `CameraScreen.kt`：`progressState` 默认值 `1f → 0f`
- `ViewfinderFrame.kt`：将"黑边框由 layout 层 padding"改为"draw 层 `Modifier.border`"
  - 原因：原来用 `padding(borderDp)` 会把内层 AndroidView 缩小；折叠态（小岛）时高度被吃成 0，PreviewView 的 Surface 为 0，cameraX 永不 STREAMING，焦段 / 手动参数失效
  - 改为 draw 层 border 后，AndroidView 始终占满外框，折叠态时 `isW × isH` 非零，相机持续 STREAMING
  - 视觉：折叠态 border 厚度 = 岛高，恰好覆盖整张小岛 → 纯黑灵动岛外观
- `ViewfinderFrame.borderDp` 参数类型 `Int → Float`

### 2. 深色模式下拍照按钮毛边
- `ShutterButton.kt`：
  - 加 `Modifier.graphicsLayer { compositingStrategy = CompositingStrategy.Offscreen }` 强制离屏合成，消除圆+描边在深色背景上的子像素杂色
  - 内层加一个 72dp 极细同色描边环（色 `#E6DCC9`），把抗锯齿过渡带埋进同色系

### 3. 缩短按下快门到开始动画的间隔
- `CameraViewModel.takePhoto()`：
  - `onImageSaved` 后**立即** `viewModelScope.launch { _photoCaptured.emit(file) }`（不等 addPolaroidFrame）
  - `addPolaroidFrame` 放后台 `viewModelScope.launch { withContext(IO) { addPolaroidFrame(...) }; refreshPhotos() }` 异步跑
  - `lastLocation` 在 `onImageSaved` 入口先快照到局部变量再清零，避免后台 addPolaroidFrame 任务读不到
- `CameraScreen.kt`：移除 `LaunchedEffect(Unit) { vm.photoCaptured.collect { ... } }` 中的 `delay(10L)`（两个分支都删）

### 注意事项
- addPolaroidFrame 后台跑时，CaptureTransitionOverlay 的 `AsyncImage` 可能读到原图（缓存命中）或处理后图（如果 addPolaroidFrame 已写回）。相册最终显示的是 Polaroid 后的图（refreshPhotos 在 addPolaroidFrame 之后调用）
- 折叠态时 PreviewView 的 Surface 尺寸 = `isW × isH`（小但非零），STREAMING 可正常 fire

## 第二轮修复：深色岛灰边 + 拍照动画流程修正

### 1. 深色模式折叠态岛灰边丢失

### 2. 拍照后的正确动画流程
**问题根因：** `_photoCaptured.emit` 过早触发 + AsyncImage 立即加载，导致 Coil 缓存了原始 JPEG，过渡全程和相册初版都"无白框"；且相册刷新时序乱，照片不出现。

**修复：**
- **`CaptureTransitionOverlay.kt`**：新增 `showPhoto` 状态，初始 `false`；在 Morph+Extend（~880ms）完成后设为 `true`，AsyncImage 仅在 `showPhoto = true` 时渲染。此时 addPolaroidFrame（~880ms 内通常完成）已写完带白框版本，Coil 直接读到 Polaroid 图。
- **`CameraScreen.kt`**：`onAddToAlbum` 改为**先** `setPlaceholder(file)` **再** `refreshPhotos()`，防止相册短暂闪现原图。
- **`CameraViewModel.kt`**：保持"立即发射 + 后台 addPolaroidFrame + 后台 refreshPhotos"结构不变。

**流程：**
1. `_shutterFlash.tryEmit(Unit)` → 白闪
2. `_photoCaptured.emit(file)` → 过渡立即开始（Morph+Extend，无照片）
3. 后台 `addPolaroidFrame(file)` 写白框
4. `showPhoto = true` → AsyncImage 加载磁盘文件（已是 Polaroid 版）
5. Emit → 打印出带白框的照片
6. Grow → 照片放大到中央预览
7. Shrink → 灵动岛缩回正常尺寸
8. **`onAddToAlbum`**: `setPlaceholder` + `refreshPhotos` → 相册首位**透明**占位（`Color.Transparent`，无可见元素）
9. 用户退出 → `close()` 飞入占位 → `clearPlaceholder` + `refreshPhotos` → Polaroid 照片出现在相册

**注意：** 背景不再 `refreshPhotos`——相册在整段动画期间没有任何变化。

## 第四轮修复：相册性能 + Polaroid 缓存

### 问题
1. 相册照片多时 LazyVerticalGrid 卡顿——`SubcomposeAsyncImage` 每格都调用 `painter?.intrinsicSize` 导致 layout shift，且以全分辨率解码
2. 连续快速拍照时，相册缩略图显示的是**原始 JPEG**（无白框），点进详情却有白框；重启 App 才正常——Coil 内存缓存 key = `file.path`，addPolaroidFrame 修改文件后 key 不变，缓存命中旧版本

### 修复方案

**`CameraViewModel.kt`**：
- 新增 `_photoVersion: MutableStateFlow<Long>` + `.asStateFlow()` 公开 `photoVersion`
- `refreshPhotos()` 在更新 `_photos` 后同时递增 `_photoVersion = System.currentTimeMillis()`

**`CameraScreen.kt` — GridPhotoCard**：
- 新增参数 `photoVersion: Long`
- 用 `remember(file, photoVersion) { BitmapFactory.Options(inJustDecodeBounds) }` **预读照片比例**，消除 `painter?.intrinsicSize` 的 layout shift
- `SubcomposeAsyncImage` 改用 `ImageRequest.Builder`：
  - `.size(200)` → Coil 按 200px 解码缩略图，不再加载全分辨率
  - `.memoryCacheKey("thumb_${file.path}_$photoVersion")` → 版本变则 key 变，缓存失效，强制加载 Polaroid 版
  - `.crossfade(300)` → 加载完成 300ms 淡入

**`CameraScreen.kt` — 占位**：
- 相同优化：预读比例 + `ImageRequest` + 版本 key + crossfade

### 效果
- 缩略图始终稳定比例，`LazyVerticalGrid` 无反复 layout shift → 丝滑滚动
- 拍完照 `refreshPhotos()` 后 `photoVersion` 递增 → 所有单元格 memory cache key 变化 → 回源读磁盘（此时文件已是 Polaroid 版）→ 缩略图正确显示白框

## 第八轮修复：GridPhotoCard 无动画拍照时 1:1 比例 bug

### 问题
关闭"开启动画"开关时，拍照后相册第一张照片显示为 **1:1**（而不是原图 4:3 或带白框后的实际比例）。

### 根因分析（关键：不是延迟问题，是写入时序问题）
1. `takePhoto` 中 `addPolaroidFrame(file)` 在 IO 协程里跑：读原图→旋转→滤镜→加白边→`FileOutputStream(file).compress(JPEG, 95)` 覆盖写回原路径（**写过程中文件被截断**）
2. 同时 `photoCaptured.collect` 无动画分支**立即**调 `vm.refreshPhotos()` → `_photos` 立即含新文件
3. `GridPhotoCard` 第一次渲染执行 `remember(file) { BitmapFactory.decodeFile(...) }`，此时 addPolaroidFrame 还在写文件 → decode 失败 → `outWidth=0` → 走 `else 1f` → **1:1**
4. 之后 `_photoVersion` 更新但 `remember(file)` 不重算（key 只有 file），**永远卡在 1f**

**Overlay 没事**因为它在 Extend 完成后**等 `photoVersion` 变化**才 `showPhoto=true`，那时 addPolaroidFrame 已写完。

### 修复方案（写入完成才入列，不靠延迟）
- **`CameraViewModel.takePhoto`**：`addPolaroidFrame` 完成后**才** `listPhotos` + 更新 `_photos` + 更新 `_photoVersion`
- **`CameraScreen.photoCaptured.collect` 无动画分支**：移除 `vm.refreshPhotos()`（VM 内部已处理）；改为轮询 `vm.photoVersion.value` 变化后才释放 `animating`

### 效果
GridPhotoCard 第一次渲染时文件已是带白框的完整版 → `BitmapFactory.decodeFile` 解出真实尺寸 → 比例正确。**带动画流程无影响**（overlay 路径独立，close() 的 onAddToAlbum 走 `refreshPhotosSync` 不更新 photoVersion）。

### 经验教训
- 涉及"异步覆盖写文件 + 立即通知 UI 渲染"时序，**必须**确保 UI 第一次渲染读到完整文件，否则 `BitmapFactory.decodeFile` 会返回 0×0
- 用 `remember(file)` 单 key 不够安全，应该同时监听"写入完成"信号（这里是 `_photoVersion`），写入未完成就不让文件进入列表

## 第九轮修复：GridPhotoCard 拍照后"第一个照片闪烁"

### 问题
1:1 比例修好后，无动画拍照时第一个照片**闪烁一下**——相册从"空状态/向下滑动打开相机"突然变成 1 张照片的 LazyVerticalGrid。

### 根因
- `addPolaroidFrame` 异步跑（~200-500ms）期间相册保持空状态
- addPolaroidFrame 完成后 `_photos` 突变含 file → `LazyVerticalGrid` 首次出现
- `GridPhotoCard` 第一次渲染时 AsyncImage 无任何淡入，从"卡片背景"突变到"卡片+图"

### 修复方案（用占位 cell 机制让相册立即有"视觉一致"的格子）

**`CameraViewModel.kt`：**
- 新增 `_photoProcessing: MutableStateFlow<Boolean>` + `photoProcessing: StateFlow<Boolean>`
- `takePhoto.onImageSaved` 改为：
  - **同步** `setPlaceholder(file)` + `_photoProcessing = true`（保证 emit 时 placeholder 已就位）
  - launch A: `emit`
  - launch B: `listPhotos` → `_photos` + `_photoVersion`(T1) → `addPolaroidFrame` → `_photoVersion`(T2) + `_photoProcessing = false`
- **不在** addPolaroidFrame 完成后自动 `clearPlaceholder()`——由 UI 端控制时机（避免与带动画 close() 流程冲突）

**`CameraScreen.kt` photoCaptured.collect 无动画分支：**
- 移除 `vm.refreshPhotos()`
- 轮询 `vm.photoProcessing.value` 变 false → `vm.clearPlaceholder()` + `animating = false`
- clearPlaceholder 后 GridPhotoCard 走 else 分支，**新组合项创建** → `remember(file)` 第一次执行 → 读到完整带白框文件 → 正确比例

**`CameraScreen.kt` 占位 cell：**
- 背景从 `Color.Transparent` 改为 `surfaceCard(isDark)` + `border(...)`（与 GridPhotoCard 视觉一致）
- `placeRatio` key 从 `remember(file)` 改为 `remember(file, photoVersion)`（addPolaroidFrame 完成后盒子比例也正确）

**`CameraScreen.kt` GridPhotoCard：**
- `ImageRequest` 加 `.crossfade(300)` → 拍照后从占位 cell 切换时图片 300ms 淡入，平滑过渡

### 关键不变量
- `setPlaceholder` 必须在 `onImageSaved` **同步**设置（不放在 viewModelScope.launch 里），否则 emit 触发 UI collect 时 placeholder 未就位，GridPhotoCard 会渲染真实图片（且文件还在被 addPolaroidFrame 写入）
- `clearPlaceholder` 必须在 `_photoProcessing = false` **之后**（保证 addPolaroidFrame 完成 + 文件已带白框），否则 GridPhotoCard 第一次渲染读到残缺文件
- 占位 cell 视觉必须与 GridPhotoCard 一致（卡片色 + 边框），否则"占位 → 真实"切换看起来像两个不同的东西
- 带动画流程不受影响：相册在 `inDetail = true` 期间被模糊，占位 cell 不可见；close() 流程中 onExit 调 `vm.clearPlaceholder()` 仍然生效

### 经验教训
- 用 StateFlow 信号（`_photoProcessing`）比轮询 photoVersion 变化次数更稳定、更易读
- 占位 cell 的视觉一致性是消除"闪烁"感知的关键——看不见的内容变化，用户无感；可见的布局/背景跳变才是真正的闪烁

## 第十轮修复：占位 cell 完全透明 + 比例正确 + 模糊层级重构

### 问题
1. 占位 cell 之前改成了 `surfaceCard(isDark)` + border（视觉与 GridPhotoCard 一致），用户要求**完全透明**
2. 无动画时占位 cell 比例 1:1 需要修复
3. 预览照片时模糊层级有问题：模糊应该是和背景颜色**一个层级**

### 模糊层级根因（用户原话："模糊应该是和背景颜色一个层级的"）
**当前**结构：
- `CameraContent` 整体 Box 套 `Modifier.graphicsLayer { BlurEffect(35px) }`（**整个相机内容层**被模糊：取景框 + 操控区 + **相册**）
- CaptureTransitionOverlay 在该模糊 Box 之外（照片、按钮清晰）

**问题**：相册、操控区都被模糊——用户应该能看到相册里的其他照片（相册不该模糊）。

**修复目标**："模糊 = 背景颜色"合成一层（与 scrim 同一个 visual layer）。

### 修复方案

**`CameraScreen.kt`：**
- **移除** `var inDetail by remember { mutableStateOf(false) }`
- **移除** `blurRadius` / `blurActive` / 模糊包装 Box
- `onDetailState = { }`（no-op；保留参数以兼容 CaptureTransitionOverlay 签名）
- 清理多余的 `}` 关闭（删除模糊 Box 后少一个 `}`）
- **相机内容层（取景框 / 操控区 / 相册 / 效果面板）全部清晰**

**`CaptureTransitionOverlay.kt`：**
- **在 overlay 根 Box 内、scrim 之前**加 AsyncImage 模糊背景层：
  - `if (showDetail) { AsyncImage(model = file, ..., graphicsLayer { BlurEffect(35px, 35px, TileMode.Decal) }) }`
  - 独立 `memoryCacheKey = "bg_${file.path}_$photoVersion"`（避免与主照片冲突）
  - `TileMode.Decal` 只模糊本层，**不影响兄弟节点**——照片、按钮在 scrim 之上仍清晰
- scrim 半透明背景色（保留）— 覆盖在模糊背景上 → 模糊 + scrim 视觉合成一层

**`CameraScreen.kt` 占位 cell：**
- 背景从 `surfaceCard(isDark)` + border 回退到 **`Color.Transparent`**（用户明确要求完全透明）
- `placeRatio` key `remember(file, photoVersion)`（addPolaroidFrame 完成后 photoVersion 变化 → 重算读到完整文件 → 正确比例；占位透明，比例跳变用户无感）

### 视觉 z-order（CaptureTransitionOverlay 内）
1. **模糊背景层**（AsyncImage 模糊照片，showDetail 时显示）— 视觉最底层
2. **scrim**（半透明背景色）
3. 灵动岛外壳
4. 照片图层（AsyncImage 清晰）
5. 顶部常驻灵动岛
6. 按钮行（清晰）

### 经验教训
- 模糊**只作用于 AsyncImage 背景层**（兄弟节点不受影响）— 照片、按钮、相册全部清晰
- scrim 覆盖在模糊背景上 → 视觉上"模糊 = 背景颜色"合成一层
- TileMode.Decal 是关键：用 Clamp/Mirror 会把模糊延伸出 Box 边界，可能影响下方
- 移除相机内容层模糊后，**相册完全清晰**——用户能看到相册里的其他照片（之前被模糊遮挡）

## 第十二轮：CameraScreen.kt 编译错误修复

### 报错
5 个错误，全部指向 `CameraScreen.kt`：
- `Unresolved reference 'PermissionRequest'`（L186）
- `Unresolved reference 'GridPhotoCard'`（L526）
- `Modifier 'private' is not applicable to 'local function'`（L719, L786）

### 根因
`CameraContent` 内部少了一个 `}`（关 L494 `} else {` 开的 else 块），导致 `GridPhotoCard` 和 `PermissionRequest` 被吞进 `CameraContent` 内部变成"局部函数"，`private` 修饰符不再适用；同时 CameraContent 也没正常结束，把下面的顶层函数拖进了它的作用域。
顺带：原 L715 的 `}   // 关闭 Box` 注释是误标，实际关的是 Column camera（L393）；Box outermost（L390）无人关。

### 修复
- L644 新增 `}   // 关闭 else (空相册 / 有相册)`（16 空格，匹配 L477 if）
- L715 拆为 `}   // 关闭 Column（相机内容）`（8 空格）+ `}   // 关闭 Box`（4 空格）+ `}   // 关闭 CameraContent`（0 空格）

### 验证
`./gradlew compileDebugKotlin` → `BUILD SUCCESSFUL in 14s`

### 经验教训
- 第十轮"清理多余 `}` 关闭"那步多删了一个，应该先 `grep -c '{'` vs `}` 数量核对（虽然注释里的字符会干扰），再决定删/补
- 注释误导也是 bug 温床：原 L715 注释"关闭 Box"但实际关的是 Column，下次重构时如果按注释改就又错了
