## 09:00 修复取景框定位偏上 + 持久化读取显示为默认两问题
1. 定位偏上根因：主界面取景框原用相机区容器高度 availH（约388dp）作 posY 参考，设置页用半屏 halfHpx（约400dp），两处参考区高度不同且框中心基准不同（容器中心 vs 半屏中心），导致相同 posY 映射出不同绝对位置、整体偏上。
   - 修复：主界面改用与设置页同一参考系——`halfHpx = screenHeightDp/2`，用 `onGloballyPositioned{ containerTopPx = positionInWindow().y }` 精确拿容器在窗口的 top，框中心屏幕 y = halfHpx/2 + (posY-0.5)*maxOff（maxOff=halfHpx-framePx），offset = 中心 - frame/2 - containerTopPx。设置页 halfHpx 也改用 configuration.screenHeightDp 同源（替代原 maxHeight*0.5），两处完全一致、所见即所得。
2. 持久化读取显示为默认根因：`LaunchedEffect(cfg){ if(!initialized){...; initialized=true} }`——首次组合 cfg=initialValue(默认) 即把 initialized 锁死，DataStore 真实值到达时不再同步，故每次进页面都是默认。
   - 修复：去掉 initialized 锁，改为 `LaunchedEffect(cfg){ 直接同步 posY/width/corner（及灵动岛的 posX/posY/width/height/corner） }`。拖动只改本地 state 不写盘、cfg 不变不打断；松手 commit 后 cfg 回写相同值也不跳变。两个设置页（ViewfinderSettingsActivity / DynamicIslandSettingsActivity）均修复。
- 编译坑：onGloballyPositioned 在 `androidx.compose.ui.layout`（非 foundation.layout）；positionInWindow 是同包扩展需 import；需 `kotlin.math.roundToInt`。
- 编译：`assembleDebug` BUILD SUCCESSFUL，产物 app/build/outputs/apk/debug/app-debug.apk。

## 11:17 音乐灵动岛：解释"为何没系统灵动岛" + 补 AudioFocus + 提升音量为真实可闻
- 用户疑问：点"调起音乐播放"为什么没调用系统灵动岛。
- 根因澄清：①**Android 无系统级灵动岛公开 API**；iOS 风格顶部药丸是 OEM/ROM 功能，普通 app 不能调用。②当前用的是标准 MediaSession+MediaStyle 媒体通知：系统会给出"通知栏媒体通知+锁屏 Now Playing 芯片"，仅少数厂商 ROM 在媒体播放时显示顶部药丸。③真正缺的是**未请求 AudioFocus**——很多厂商灵动岛/媒体药丸靠"持有音频焦点+真实音频轨"判断，不抢焦点就不触发；且原音频振幅仅 0.06（-24dB）过轻。
- 改动 `dynamic/MusicIslandService.kt`：play() 调 `requestFocus()`、pause()/stop() 调 `abandonFocus()`；新增 `audioManager`/`focusRequest` 字段与 requestFocus/abandonFocus（API26+ 用 AudioFocusRequest，低于用旧 API 兼容）；播放属性设为 USAGE_MEDIA/CONTENT_TYPE_MUSIC。
- 资源：`res/raw/island_tone.wav` 由 Python 重新生成为 振幅0.25（-12dB，清晰可闻）、330Hz、2s、无缝循环（330*2=660 整数周期）、16bit mono 44.1kHz；脚本用后删除。
- 说明：上述改动最大化触发"系统媒体 UI/厂商药丸"的概率，但**原生 Android/模拟器仍只有媒体通知、无顶部药丸**；要稳定可见的 iOS 风格药丸必须在 app 内自绘 overlay（用已配 posX/posY）或全局悬浮窗（需 SYSTEM_ALERT_WINDOW）。已向用户说明并询 A(应用内药丸)/C(全局悬浮窗)/B(保持) 方向。
- 编译：`assembleDebug` BUILD SUCCESSFUL，产物 app/build/outputs/apk/debug/app-debug.apk。

## 11:25 音乐通知进度条/时间不显示 → 补 metadata 时长 + 周期上报播放位置
- 根因：`PlaybackStateCompat` 用 `PLAYBACK_POSITION_UNKNOWN` 且从不设 `MediaMetadataCompat`（无时长），也从不更新播放位置 → 媒体通知无"已播/总时长"，进度条与时间缺失。
- 改动 `dynamic/MusicIslandService.kt`：
  - 新增 `toneDurationMs`（onCreate 取 `player.duration`，缺省2000），及 `progressHandler`/`progressRunnable`（主线程每 1000ms 调 `updatePlaybackState()` 刷新位置）。
  - 新增 `updateMetadata()`：设 `METADATA_KEY_TITLE="灵动岛示意"`/`ARTIST="Picocam"`/`METADATA_KEY_DURATION=toneDurationMs`，play() 时调用。
  - `updatePlaybackState()`：`setState(state, pos, 1f)`，pos 取 `player.currentPosition`（播放中），暂停/停止为 0；移除 `PLAYBACK_POSITION_UNKNOWN`。
  - play() 启动进度刷新；pause()/stop() 用 `progressHandler.removeCallbacks(progressRunnable)` 停止刷新。
  - 新增 import：`android.os.Handler`/`Looper`、`android.support.v4.media.MediaMetadataCompat`。
- 说明：示意音为 2s 无缝循环，故通知进度会随循环走 0→2s 往复；若用户觉得 2s 太短像"不正常"，可把循环音时长拉长或改为显示较长固定总时长。
- 编译：`assembleDebug` BUILD SUCCESSFUL，产物 app/build/outputs/apk/debug/app-debug.apk。
