## 第七十二次（13:18）：内容层改用 Row+Spacer——修复背景不显示 + 有调色盘时塌陷
文件：`EffectsPanel.kt`
- 用户反馈：上轮「纯 background+显式子 Box」方案两个截图都失败：
  - 无调色盘：背景/渐变全没显示，滤镜列表直接浮在相册上
  - 有调色盘：右侧元素整个消失
- **根因**：`Box(fillMaxSize).padding(end=...).contentAlignment=CenterEnd` 组合在窄容器中**塌陷**：
  - `fillMaxSize()` 让内容 Box 占满整个右侧元素，即使没有 background 也会占据布局
  - 当右侧元素较窄（调色盘出现时只有 143dp），`contentAlignment=CenterEnd` 配合 `width(filterListWidth)` 导致整个布局塌陷为 0
  - 同时 `fillMaxSize` 占据布局后，下层实色背景/渐变被遮住
- **修复**：内容层从 Box+contentAlignment 改为 **`Row + Spacer(weight=1f) + Column`**：
  ```kotlin
  Row(Modifier.fillMaxSize().padding(end = controlInset)) {
      Spacer(Modifier.weight(1f))  // 弹性空间，把 Column 推到右边
      Column(Modifier.fillMaxHeight().width(filterListWidth).clip(RoundedCornerShape(20.dp))) {
          // 滤镜列表 + 还原
      }
  }
  ```
  - Row 是线性布局，Spacer(weight=1f) 占满剩余空间，Column 自然贴右
  - **不用 contentAlignment、不用 fillMaxSize 套在内容外层**——这是 Compose 最稳的右对齐模式
- 背景/渐变结构不变（1. 嵌套Box+padding 主体实色 / 2. 独立Box 左渐变 / 3. 独立Box 下渐变），外层 Box 无背景透明
- 验证：`BUILD SUCCESSFUL in 3s`
- **关键经验**：`contentAlignment` + `fillMaxSize` 组合在窄容器中容易塌陷，**右对齐用 Row+Spacer(weight=1f) 更稳**

## 第七十一次（13:09）：从头重构——彻底放弃 drawWithContent，纯 background + 显式子 Box
文件：`EffectsPanel.kt`
- 用户要求从头梳理实现方式，之前所有方案（drawBehind / drawWithContent / .background 外层+子Box clip）都有问题。
- **根因总结**：
  - `drawWithContent` / `drawBehind` 创建的 graphics layer 透明区域**不透出底层相册** → 渐变看不见
  - `Modifier.clip()` 在有背景的 Box 上会创建不透明 graphics layer → 遮住下层背景 → 圆角露馅
  - `Modifier.align()` 在 `drawWithContent` 的 Box 内做子元素右对齐时渲染异常 → 右侧元素消失
- **全新方案**：彻底放弃 `drawWithContent`，改用**纯 `Modifier.background()` + 显式子 Box**：
  ```
  右侧元素 Box (weight 1f, 无背景, 透明)
    ├─ 1. 主体实色: 嵌套Box(padding start=56,bottom=32) → 内层Box.background(cream)
    │     （嵌套+padding 确保实色只覆盖主体区，不覆盖渐变区）
    ├─ 2. 左渐变: Box(width=56, padding bottom=32).background(horizontalGradient 透明→cream)
    ├─ 3. 下渐变: Box(height=32, align=Bottom).background(verticalGradient cream→透明)
    └─ 4. 内容: Box(padding end=controlInset, contentAlignment=CenterEnd)
         └─ Column(width=filterListWidth, clip=20dp) { 滤镜列表+还原 }
  ```
  - 外层 Box **无背景**（透明）→ 渐变区的透明端天然透出相册
  - 主体实色用**嵌套 Box + padding**让出渐变区（`background` 在内层 Box 上，只画 padding 后的区域）
  - 渐变用独立子 Box（`Modifier.background(Brush)` 是基础 modifier，绝对生效）
  - 内容用 `contentAlignment = CenterEnd` 做右对齐（不用 `Modifier.align()`）
- 移除 `drawWithContent` import（不再使用）
- 验证：`BUILD SUCCESSFUL in 3s`

## 第六十五次（12:37）：背景最终方案——drawWithContent 手动画 + 原生 Canvas 裁剪
文件：`EffectsPanel.kt`
- 用户反馈：第六十四次的「外层 Box .background() + 子 Box 渐变 + 圆角内容层 clip」**仍未生效**——右侧仍露出相册，左/下渐变仍不可见。
- **根因分析**：之前四轮尝试（`drawBehind` 写在 `.then()` / 独立 drawBehind 子 Box / 外层 `.background()` + 子 Box clip / 等）都存在同一类问题——`clip` 创建的 graphics layer 在某些渲染路径下会**遮住下层背景**，导致右侧/角落透出底层相册。
- **本轮最终方案**：用 `Modifier.drawWithContent` 把背景和内容**画在同一个绘制流程**中，物理上保证背景永远先画：
  1. 在 `drawWithContent` lambda 内（receiver = `ContentDrawScope`）依次 `drawRect(bgColor)` / `drawRect(左侧渐变)` / `drawRect(下侧渐变)`——这三步画的是**直角矩形**（满铺整个外层 Box），物理上不可能露馅。
  2. 然后用 `drawIntoCanvas { canvas -> canvas.save(); canvas.clipPath(clipPathObj) }` 在原生 Canvas 上叠加一个**圆角 clipPath**。
  3. 紧接着调用 `drawContent()`——此时 Canvas 已被裁剪为圆角，内容自然被裁成圆角。

## 18:50 修复「冷色滤镜下饱和度方向反了」——buildFilterColorMatrix 操作顺序
- 现象：冷色滤镜下，往右（dotX 增大）应饱和度变高，实际感觉往左才更饱和。
- 排查：CameraViewModel.effective 的 saturation=(dotX-0.5)*2*SAT_SCALE(=1)、shader、FilterMatrix 三处对 warm/cool 完全对称，无 cool 专属反相逻辑；SAT_SCALE 正。预览走 ViewfinderFrame 的 RenderEffect + buildFilterColorMatrix（ColorMatrix 路径，非 GLSL）。
- 根因：`buildFilterColorMatrix`（app/.../camera/FilterMatrix.kt）操作顺序为 饱和度→曝光→色温→灰度，把【色温放到饱和度之后】。而 GLSL(filter_fragment.glsl)顺序是 曝光→色温→饱和度→灰度（色温在饱和度之前）。冷色的蓝移(warmth<0: r-0.15,b+0.15)在旧顺序里是最后一层"平坦加色"不被饱和度放大 → 往右加饱和只放大画面原有偏暖/中性色再糊平蓝=浑浊；往左去饱和(→灰)再加平蓝=更干净的蓝，于是左右观感颠倒。暖色因蓝/红移与暖色场景叠加方向一致，差异不明显故没被察觉。
- 修复：重排 buildFilterColorMatrix 为 曝光→色温→饱和度→灰度（依次 postConcat；postConcat(M)=cm=M*cm，故 postConcat 顺序即像素经历顺序），与 shader 对齐。饱和度改用 `ColorMatrix().apply{setSaturation(1+s)}` 再 postConcat（原为直接 cm.setSaturation 会重置矩阵，必须先做曝光/色温）。预览与保存(PhotoStorage 共用此函数)一并修正、保持一致。warm/cool 仍对称。
